# 发布流程（v1.1.0）

## 一、发布前必须确认

| 检查项 | 说明 |
| --- | --- |
| 云函数重新部署 | `cloudfunctions/login`、`cloudfunctions/room` 都要右键「上传并部署：云端安装依赖」。**room 本次改动很大（新增 leave 移交房主、submitScore、avatarUrls 临时链接），不部署会直接报「未知操作」** |
| 云环境 ID | `app.js` 中 `env: 'cloud1-6gd9msfpc3b53edf'` 必须是正式环境 |
| 数据库集合 | 云开发控制台需存在 `rooms` 集合；权限建议设为「仅管理端可读写」（客户端全部走云函数） |
| 云存储权限 | `avatars/` 目录权限建议「仅创建者可读」，头像由云函数换临时链接下发 |
| 隐私保护指引 | mp 后台「设置 → 服务内容声明 → 用户隐私保护指引」需声明：头像（相册/相机）、上传图片、剪切板（复制房号）。未声明时线上调用 `chooseAvatar` / `setClipboardData` 会失败 |
| 类目 | 建议选「工具 → 效率」等普通类目，**避免选到「棋牌」类目**（棋牌类需要额外资质/版号，会被驳回） |
| 包体 | 已忽略测试数据 `database_export-*.json`、样式备份 `room_backup.wxss`、说明文档，主包很小 |

## 二、上传代码

1. 微信开发者工具打开项目根目录 `wx_xcx`（appid: `wx99e76f2c0508a6df`）
2. 先本地「编译」跑一遍：开房 → 另一台设备/另一个微信号进房 → 双方互相记分 → 退出房间，确认分数与房主移交正常
3. 点击右上角「上传」：
   - 版本号：`1.1.0`
   - 项目备注：`v1.1.0 头像云端化 + 计分/轮询优化 + 房主移交修复`（详细说明见 CHANGELOG.md）

## 三、提交审核与发布（可直接复制的文案）

1. mp.weixin.qq.com → 管理 → 版本管理 → 开发版本 → 选中 `1.1.0` → 「提交审核」
2. **版本描述**（平台限 200 字，以下为 194 字，可直接复制）：

```
【功能】线下牌局、聚会计分工具。开房生成4位房号，好友输入房号进房；点击他人头像输入分数，给对方加分时自己扣相同分数，房内实时同步分数与记录，最后一人退出时房间自动解散。【路径】首页设置头像昵称→我要开房→复制房号→另一微信号输房号进房→点击头像记分→退出房间。【说明】头像昵称由微信头像昵称填写能力授权获取，仅用于房内身份展示；数据存储于微信云开发，无第三方SDK、无支付、无对战玩法。
```

> 若审核备注栏字数更宽松，可补充：本小程序不含棋牌游戏本身玩法、无虚拟支付与兑换、无用户内容公开发布；建议用两个微信号分别「开房」与「进房」验证记分同步。


3. **审核备注 / 测试信息**（如页面上有单独填写项）：

```
测试微信号：无需指定账号，任意微信号可直接体验
测试路径：开房 → 复制房号 → 另一个微信号输入房号进房 → 互相记分 → 退出房间
备注：本小程序为线下聚会记分工具，不含棋牌游戏本身玩法，不涉及任何付费或兑换
```

4. **隐私保护指引**需在「设置 → 服务内容声明 → 用户隐私保护指引」中勾选并填写用途：
   - 剪切板 →「用于复制当前房间号，便于分享给同局好友加入房间」
   - 选中的照片或视频信息 →「用于选择并设置你的房间头像，仅在本房间内展示」
   - 微信昵称、头像 →「用于在房间内展示玩家昵称与头像，便于区分同桌玩家」
   - 摄像头先不勾（扫码进房按钮已隐藏，恢复时再补）
   - 存储期限不要填 0 天，建议 90~180 天；「你的权益」中的联系方式必须填写邮箱
5. 审核通过后点「发布」（可选全量发布/分阶段发布）。

> 注意：类目请选「工具 → 效率」等普通类目，不要选「棋牌」类目（需要版号等资质，会被驳回）。


## 四、回滚

- 线上异常：版本管理 → 选择旧版本「版本回退」
- 云函数异常：云开发控制台 → 云函数 → 版本管理 → 回滚到上一版本
